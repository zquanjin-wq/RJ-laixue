# RJ-laixue 研发天团 · 使用说明

## 这是什么

RJ-laixue 项目的本地 3 模型协作团队，**真正 3 个不同模型并行/串行**处理一个研发任务：

| 角色 | 模型 | 任务 |
|------|------|------|
| 🎯 见远（架构师） | Kimi K3 | 需求拆解、技术方案 |
| 💻 动手（工程师） | DeepSeek V4 Pro | 写代码 |
| 🔍 严测（测试员） | MiniMax M3 | 跑测试、验证 |

工作流：见远出方案 → 动手写代码 → 严测验证 → 最终汇总。

## 怎么用

### 准备：配置 3 个 API Key

打开项目根目录的 `.env.local` 文件（已经有 MiniMax 的 Key），**追加 3 行**：

```bash
# 已有（请保留）
KIMI_API_KEY=sk-你的KimiKey
DEEPSEEK_API_KEY=sk-你的DeepSeekKey
MINIMAX_API_KEY=sk-你的MiniMaxKey
```

> ⚠️ 如果 `.env.local` 已经有 MiniMax 相关的变量名（如 `TTS_MINIMAX_API_KEY`），**不要删**，**只**追加上面 3 行。

### 跑一个任务

打开 **PowerShell**（或终端），`cd` 到 RJ-laixue 项目根目录：

```powershell
cd "D:\WorkBuddy 地界\RJ-laixue"
pnpm dev-team "修复用户登录页面的样式错位"
```

### 控制台输出乱码？

PowerShell 默认 GBK 编码，会让 emoji 出乱码。
**修复方法**：在 PowerShell 里先跑：

```powershell
chcp 65001
```

或者看我给你的命令截图。

## 常见问题

### Q1：跑时报 "缺少 KIMI_API_KEY" 怎么办？
A：检查 `.env.local` 文件，确认 3 个 KEY 都存在。文件改完后**不用重启**，跑 `pnpm dev-team` 会重新加载。

### Q2：跑了几分钟后报 "fetch failed" 怎么办？
A：通常是某个模型 API 临时挂了。直接重跑一次 `pnpm dev-team "..."`。每个模型独立，3 个里 1 个挂不影响其他。

### Q3：3 个模型给了互相矛盾的方案怎么办？
A：**这种情况是真实的**。比如见远说改 A 文件，动手说改 B 文件。**最终决策权在你**：
- 觉得见远对 → 接受见远方案，让动手按见远方案重写
- 觉得动手对 → 接受动手的，告诉见远"你的方案 X 不好"
- 都觉得不对 → 重新跑一次，或者直接自己手动改

### Q4：能不能一次只叫 1 个角色？
A：现在不能（单任务版）。后续可加 flag：`pnpm dev-team --only=architect "..."`

### Q5：报告保存在哪里？
A：`dev-team-output/` 目录下，按时间戳命名。

### Q6：能不能改 prompt？
A：可以，编辑 `lib/orchestration/dev-team-graph.ts` 里的 `ARCHITECT_SYSTEM_PROMPT` / `DEVELOPER_SYSTEM_PROMPT` / `TESTER_SYSTEM_PROMPT` 三个常量。改完直接跑生效。
