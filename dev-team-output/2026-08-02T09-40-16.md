### 要改的文件
- `app/(auth)/login/page.tsx`（若无 auth 路由组则为 `app/login/page.tsx`）：修复页面最外层容器的布局类（居中、高度、padding），改动范围通常在 `return` 语句的最外层 `<div>`，约 1–3 个 className
- `components/auth/LoginForm.tsx`（如存在）：修复表单卡片内部的宽度约束与对齐（`w-full max-w-md mx-auto` 一类），仅改 className
- `app/globals.css`：**仅当** DevTools 确认错位由全局样式冲突引起时才改，且只追加/修正冲突规则，不动 reset 和 CSS 变量区块

### 改动概要
0. **先定位**：运行 `pnpm dev` 打开登录页，DevTools 审查错位元素，确认根因属于以下哪一类：①外层容器缺 flex 居中；②`h-screen` 在移动端被地址栏挤压（应换 `min-h-dvh`）；③全局 CSS 冲突；④登录页漏套 layout 或引用了错误的全局类
1. 确认登录页路由文件的真实路径与组件拆分（page 与 Form 组件各管哪层样式）
2. 按根因修复：容器层补 `min-h-dvh flex items-center justify-center` 类结构；卡片层补宽度约束与间距类
3. 若是全局样式冲突，在 `globals.css` 用更精确的选择器修正，避免污染其他页面
4. 运行 `pnpm lint` 和 `pnpm typecheck`，并在桌面 + 移动端视口（375px）+ 至少 Chrome/Safari 各验证一次，留存修复前后截图对比

### 风险点
- 误改 `globals.css` 的 reset 或主题变量会**全站样式回归**，这是本任务最大风险

- 若项目启用了暗色模式（`dark:` 前缀），修复后要同时验证暗色下不错位
- 登录页若被 `app/(auth)/layout.tsx` 包裹，错位根因可能在 layout 而非 page，改错文件会无效甚至双重居中

### 复用的现有代码

- 如项目已有 `components/ui/*`（shadcn 风格）的 Card/Input/Button，直接沿用，不自绘
