## 1️⃣ 见远（Kimi K3）· 技术方案
## 技术方案：沿布局链路（layout → page → 表单组件）定位错位来源，修正登录页容器的高度与居中约束

> **前置说明**：任务未指明"错位"的具体表现（哪个元素、什么视口、偏哪边）。本方案按最高频的三类成因设计——①外层容器高度/居中失效 ②layout 注入的多余 padding 泄漏 ③表单卡片内元素宽度不统一。工程师必须先执行第 1 步复现确认，再对号入座。

### 要改的文件
- `app/(auth)/login/page.tsx`（或 `app/login/page.tsx`，先确认哪个真实存在）：修正最外层容器（return 根元素，通常在 L10–L30）的高度类与 flex 居中类
- `components/auth/LoginForm.tsx`（或 `components/LoginForm.tsx`）：统一卡片、输入框、按钮的宽度约束（表单容器区域，通常 L20–L60）
- `app/(auth)/layout.tsx`（如存在）：**仅当**确认错位源自 auth 布局注入的 wrapper/padding 时才动

### 改动概要
1. 复现定位：`pnpm dev` 打开登录页，DevTools 逐层检查，确认是哪个元素错位、偏移由哪一级父容器引入；桌面与移动视口各看一次
2. 梳理布局链：root layout → (auth) layout → page，判断是否有全局导航栏/页面 padding 泄漏进登录页
3. 修容器：最外层使用 `min-h-screen w-full flex items-center justify-center`（避免 `h-screen` 在移动端 100vh 包含浏览器工具栏导致溢出）；若父级存在限宽或 padding 容器，让登录页绕过该容器
4. 修表单卡片：卡片 `w-full max-w-sm`（或 `max-w-md`），输入框与提交按钮统一 `w-full`，消除左右不对齐
5. 回归验证：多视口 +（如已启用）暗色模式各检查一遍；跑 `pnpm lint` 和 `pnpm typecheck`

### 风险点
- 改 `(auth)/layout.tsx` 会波及同组所有路由（如注册页、忘记密码页），改前必须列出受影响页面逐一回归
- `h-screen` ↔ `min-h-screen` 的互换在移动端工具栏场景可能引入新的滚动/溢出 bug
- Tailwind 类冲突：同一元素上同时存在冲突类（如 `items-start` 与 `items-center`）时，生效方由生成的 CSS 顺序决定而非 class 书写顺序——必须**删除旧类**，不能只追加新类
- 若表单用的是共享 UI 组件（shadcn 风格 Card/Form），在外层覆盖样式可能影响其他复用页面

### 复用的现有代码
- `lib/utils.ts` 的 `cn()`（若存在）：合并/条件拼接 className 时使用
- `components/ui/` 下现有的 Button / Input / Card 组件：继续复用，不新造组件

### 给工程师的注意事项
- 路由组 `(auth)` 不出现在 URL 中，`/login` 实际对应的文件要先 Glob 确认
- 上述行数区间均基于标准结构的假设，读文件后以实际为准
- 遵循最小改动原则：只动导致错位的那个容器/类，不顺手重构
- 修复前后各截图一张存档，随 PR 提交便于 review

### 不要做的事
- 不要改 `app/globals.css` 和 `tailwind.config.ts`（影响全站）
- 不要重构 `app/layout.tsx` 根布局（除非已确认它是错位源头，且只做条件排除而非结构调整）
- 不要引入新的样式方案（CSS Modules、styled-components、新 UI 库）
- 不要触碰任何登录逻辑：表单提交、API 调用、鉴权、TTS 相关代码一律不动
- 不要顺手"优化"其他页面的样式
