# Laixue 从 Vercel / Supabase 迁移至火山引擎：总规划

> 版本：v0.1  
> 制定日期：2026-08-13  
> 当前状态：待执行 Gate 0  
> 长期候选：IGA Pages + AIDAP（AI Native Database Platform，Supabase 版）+ 可用的后台计算服务  
> 对照方案：EdgeOne Pages + AIDAP（Supabase 版）

> **优先级调整（2026-08-13）**：因 Vercel 额度/付费受限，先执行“Vercel 退出快车道”。快车道只替换计算与访问入口，暂时保留现有 Supabase 生产项目；AIDAP 数据迁移仍按 Gate 2 在独立窗口完成。经账号可用性核实，veFaaS 处于邀测，明确排除出紧急迁移主路径。

## 1. 决策摘要

本次迁移采用“先验证、再解耦、后迁数据、最后切流”的方式，不允许同时一次性切换计算平台与生产数据库。

首选全火山架构：

- IGA Pages：Next.js 页面、静态资源、SSR、短 API 和可控的流式响应；
- AIDAP（Supabase 版）：PostgreSQL、Auth、RLS、Storage、Realtime；
- 当前可购买的 ECS/Docker：课程生成、重新配音、PDF/图片处理等服务端任务；
- TOS：仅在 Supabase Storage 无法满足大文件、生命周期或分发需求时引入；
- IGA/DCDN：国内及全球分发，自定义生产域名须满足备案要求。

EdgeOne 仅作为 IGA Pages 兼容性或稳定性不达标时的对照与回退候选，不在首轮同时建设两套生产系统。

## 2. 已知现状与迁移约束

截至规划制定时，仓库具备以下特征：

- Next.js 16.1.2 App Router；
- 约 82 个 Route Handler；
- 多个接口声明 120～300 秒最大执行时间；
- 课程生成和重新配音使用 `next/after` 继续后台执行；
- 使用 `sharp`、`node:dns`、`node:net`、`node:async_hooks` 等 Node 能力；
- 仍有服务端本地文件读写，包括任务状态、课堂媒体、配置和用量记录；
- 数据、认证和课程资产已经较多依赖 Supabase；
- 包含 AI/SSE 流式响应、音频、PDF、PPT 和媒体上传等高风险路径。

因此迁移不能被定义为“更换部署按钮”。必须先解决运行时兼容、临时文件、后台任务、上传链路和数据库可回滚迁移。

## 3. 目标架构与责任边界

### IGA Pages 可以承载

- 页面、静态资源、SSR；
- Middleware/访问码鉴权（以实测为准）；
- 查询、保存、签名等短时 API；
- 可在平台限制内完成的 AI 流式响应；
- 健康检查、版本标识和部署观测入口。

### IGA Pages 不应承载

- 课程完整生成；
- 批量重新配音；
- PDF/PPT 重处理与 `sharp` 密集计算；
- 视频任务长轮询；
- 依赖响应结束后继续运行才能完成的任务；
- 任何依赖实例本地磁盘持久化的状态。

### 后台任务服务负责

- 持久化领取任务并维护租约；
- 幂等、重试、取消、超时和失败原因；
- 调用外部 AI/TTS/ASR/视频服务；
- 将产物直接写入对象存储；
- 将进度和最终状态写回 PostgreSQL；
- 提供健康、积压和失败任务观测。

## 4. 核心迁移原则

1. 生产数据库迁移和生产计算切换不得在同一变更窗口完成。
2. 每个 Gate 必须有通过/不通过结论、证据、回滚步骤和未决风险。
3. 所有长任务在平台切换前完成持久化异步化，不依赖 `next/after` 保证完成。
4. 所有长期数据退出本地文件系统；临时文件只能位于受控临时目录并及时清理。
5. 大文件必须采用预签名直传，避免经过 Pages Function 中转。
6. 数据迁移至少进行一次全量演练和一次增量/停写演练。
7. Vercel 和原 Supabase 在完成稳定观察前保持可回滚，不提前删除。
8. 新平台密钥不得写入仓库、日志、报告或测试快照。

## 4.1 Vercel 退出快车道

### 目标

在不迁移生产数据库、Auth 或 Storage 的前提下，先让生产请求不再依赖 Vercel。当前 Supabase 继续作为唯一事实来源，直到 AIDAP 完成独立迁移演练。

### 首选实现

当前应用包含 300 秒请求、原生 `sharp`、本地文件读写和 `next/after`，因此快车道的生产承载确定为 **火山 ECS 云服务器运行 Docker 化的完整 Next.js**，前置 Caddy/Nginx，再接入火山 DCDN。不要把完整现有应用直接押注到 IGA Pages Functions，也不依赖邀测中的 veFaaS。

- ECS + Docker Compose：完整 Node.js 20 运行时，先获得与当前 `next start` 最接近的行为；
- Caddy/Nginx：TLS、反向代理、压缩、上传大小和超时控制；
- DCDN：负责国内访问加速和生产域名入口；
- 现有 Supabase：短期继续使用，不改变数据；
- Vercel：仅作为平行回滚源，保留至新入口稳定 14 天；
- AIDAP：继续在 `laixue-migration-dev` 做兼容与迁移演练，不阻塞退出 Vercel。

### 快车道的必要改造

容器能够先解除 Vercel 时长与充值风险，但本地磁盘和 `next/after` 仍不应作为生产保证。快车道分为两层：

1. **入口切换前必做**：容器化、健康检查、环境变量、日志轮转、自动重启、文件系统风险隔离、长任务入口保护、备份与回滚；
2. **入口切换后立即做**：将课程生成、重新配音、PDF/视频等长任务改为持久化异步任务，随后才缩减容器规格或转入 Pages 函数。

### 生产门禁

- 现有 Supabase 保持不变，避免数据面与计算面同时变更；
- 长任务必须经压测确认，不允许因为容器可运行就忽略进程重启风险；
- 生产域名切换前完成备案、证书、DCDN 和 DNS 回滚演练；
- 首轮切换必须保留 Vercel 回切；
- 未经验证，不能把 IGA Pages 公测能力作为 laixue 唯一生产计算环境；veFaaS 在正式开放前不得进入生产关键路径。

## 5. Gate 与顺序

### Gate 0：基线、依赖和退出标准盘点

目标：获得可复现的现网基线和完整平台依赖清单。

交付物：

- 路由兼容矩阵：运行时、时长、请求体、流式、原生模块、本地文件、后台执行；
- Supabase 使用矩阵：表、视图、RPC、触发器、RLS、Auth、Storage、Realtime；
- 生产流量/容量基线和关键用户旅程；
- 密钥与域名清单（只记录名称和归属，不记录值）；
- PoC 测试数据与脱敏方案；
- 每条生产路径的回滚责任人和信号。

通过条件：不存在“未知所有者”的生产数据、域名或关键任务路径；PoC 入口和测试账号已准备。

### Gate 1：IGA Pages 与 EdgeOne 对照 PoC

目标：用同一提交、同一测试数据验证 Pages 层兼容性，并作出唯一平台决策。

IGA 为主候选，EdgeOne 为对照。验证：构建、SSR、Middleware、Route Handler、SSE、上传签名、图片优化、冷启动、错误日志、国内三网访问。

通过条件：

- IGA 能构建并运行 Next.js 16，或存在低成本、已验证的兼容调整；
- P0 用户旅程全部通过；
- SSE 首包、持续连接和取消行为达标；
- 不要求把长任务塞入 Pages；
- 关键限制和正式商用风险得到火山工单书面确认。

决策规则：IGA 达标则选择全火山；IGA 不达标而 EdgeOne 达标，则选择 EdgeOne；两者均不达标则改用容器承载完整 Next.js，DCDN 只负责加速。

### Gate 2：AIDAP（Supabase 版）兼容性与迁移演练

目标：证明现有 Supabase 数据面可以迁移且可回滚。

验证：schema、数据、序列、扩展、函数、触发器、RLS、Auth、Storage、签名 URL、Realtime、service role、备份恢复。

特别门槛：不能只验证普通业务表。Auth 用户、密码/登录方式、JWT、RLS 与 Storage 权限必须形成闭环。无法直接迁移密码时，必须先形成用户无损重认证方案并得到产品确认。

通过条件：

- 全量演练完成且关键表行数/校验和一致；
- P0 查询、写入、Auth、RLS 和 Storage 自动化测试通过；
- 回滚演练完成；
- Edge/Pages 到数据库的延迟和连接稳定性达标；
- RPO/RTO 有明确数值与负责人。

### Gate 3：长任务与文件系统解耦

目标：使应用不依赖 Vercel 的 300 秒函数和实例生命周期。

首批必须迁移：

- classroom generation；
- course revoice；
- document/PDF extraction and image processing；
- video generation/polling；
- 本地任务状态、课堂媒体、用量日志的持久化。

统一任务协议至少包含：`job_id`、类型、幂等键、状态、进度、租约、尝试次数、下一重试时间、错误码、输入引用、输出引用、创建/开始/完成时间。

通过条件：任务在请求返回、实例重启、重复投递和执行器崩溃后仍能正确恢复；同一幂等键不会产生重复业务产物。

### Gate 4：预生产、数据切换与灰度

目标：完成真实规模验证，并把生产风险限制在可快速回滚范围内。

顺序：

1. 预生产接入脱敏/复制数据；
2. 完整 E2E 与压力测试；
3. 降低 DNS TTL；
4. 生产数据库迁移演练；
5. 先切数据库或先切计算，二者之间保留观察期；
6. 内部用户/测试域名；
7. 小比例灰度；
8. 全量切换；
9. Vercel 和原 Supabase 保持只读或可恢复状态 14 天以上。

### Gate 5：稳定观察与下线

目标：确认新架构达到业务、性能、成本和运维目标后再结束旧平台。

通过条件：

- 连续 14 天无 P0/P1 平台相关事故；
- 错误率、任务成功率、SSE、上传和数据库延迟达到基线；
- 费用告警、备份恢复、日志和应急手册可用；
- 完成一次恢复演练；
- 产品负责人签署旧平台下线决定。

只有 Gate 5 通过后，才能取消 Vercel 付费资源和删除旧 Supabase 项目。

## 6. P0 验收旅程

每个生产候选平台都必须完成：

1. 访问码/登录与会话恢复；
2. 创建、打开、编辑、保存和再次打开课程；
3. 上传 PDF/PPT/音频并正确形成资产引用；
4. AI 对话和场景生成流式响应，支持取消；
5. 课程生成任务提交、查询、失败重试和完成；
6. 重新配音提交、执行、发布和播放；
7. 移动端课程访问和学习进度写入；
8. 管理端课程、学生和学习任务查询；
9. 签名资源访问、过期与越权拒绝；
10. 服务重启后任务、课程和媒体状态不丢失。

## 7. 非功能门槛

具体数值在 Gate 0 以现网基线冻结，默认原则：

- 新平台 P95 页面/API 延迟不得显著差于现网，国内网络必须有明显改善；
- 5xx 和未捕获异常率不得高于现网；
- 长任务成功率不得下降；
- 数据核对必须做到关键表全量一致，普通大表允许使用行数 + 分层校验和；
- 所有生产告警必须指向明确处理人和处置手册；
- 成本必须设置预算与异常增长告警，不能依赖公测免费作为商业决策。

## 8. 回滚策略

- Pages 回滚：DNS/CNAME 切回 Vercel，旧部署在观察期内不得修改或删除；
- 数据回滚：迁移窗口采用明确停写或双写策略；未经验证不得临时设计双向同步；
- 任务回滚：停止新执行器领取，等待或取消租约，将新任务入口切回旧系统；
- Storage 回滚：迁移期保留源对象，目标路径使用可重放清单，不覆盖唯一源；
- Auth 回滚：保留旧登录入口和用户映射，禁止在未验证密码迁移前强制全量切换。

## 9. 明确不在首轮做的事

- 不因迁移顺带更换全部 AI 模型供应商；
- 不同时重构学习管理产品功能；
- 不一开始引入复杂 Kubernetes；
- 不为“全火山”强行放弃已经稳定且兼容的组件；
- 不在缺少 SLA/配额书面确认时把 IGA Pages 公测环境直接设为唯一生产入口。
