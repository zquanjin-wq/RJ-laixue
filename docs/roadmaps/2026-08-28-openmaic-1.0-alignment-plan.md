## 1. 目标与事实边界

近期交付两项能力：讲师上传 PPTX，形成可编辑、带讲稿和旁白的课程；外部应用通过受控 API/Skill 在教师名下创建课程。输出必须进入现有课程列表、发布、学员权限、移动端及学习记录。

用户确认已迁至 laixue.online 和北京腾讯云轻量服务器。代码复核确认 Next.js 16、React 19、Better Auth、PostgreSQL repository/migration、腾讯 COS、Docker Compose/Caddy 已有实现。codex/production-clean、2791d73d 是此前本地审查起点，不代表已核实生产版本。

生产镜像、数据库迁移版本、主机容量、恢复演练和业务冒烟仍待核验。原 Supabase 双后端、auth.uid() 与 RLS 迁移计划退出本轮目标；身份采用 Better Auth 用户 ID，权限由当前服务端授权层执行。

## 3. 目标架构

浏览器 session / 教师调用令牌 → API 认证授权 → 生成应用服务 → PostgreSQL 任务和阶段记录 → 独立 worker → 模型/解析执行器/COS → 校验与课程事务提交。

| 组件 | 职责 |
|---|---|
| API | 校验输入、actor、限额、幂等、入队、查询与取消 |
| 生成应用服务 | 显式传递 actor/courseId/sourceRevision；不依赖请求 cookie |
| PostgreSQL | 执行权、任务、阶段索引、正式课程及最终状态的权威源 |
| COS | 来源文件、媒体、大型产物；短期签名在使用时生成 |
| Worker | 固定阶段执行、心跳、有限重试、取消检查 |
| PPT 执行器 | 运行环境由 A2 实测决定；输出统一 ImportResult |
| Skill | API 薄适配，不复制鉴权、生成和发布逻辑 |

首期继续采用 PostgreSQL、Compose 和独立 worker。Redis、通用工作流引擎、多租户及公开 Skill 市场不进入首批。

## 4. 任务、恢复与提交契约

### 4.1 数据与固定阶段

优先扩展 app.background_jobs，兼容现有消费者；生成专用信息可放关联表，DDL 在 B1 定稿。不默认建立第二套通用队列。

新增或关联：ownerUserId、credentialId、channel（web/api）、inputKind（text/pptx）、operation（create/enhance）、courseId、sourceRevision、requestHash、idempotencyKey、pipelineVersion、非秘密配置快照、执行代次、租约、取消请求、质量与警告。

渠道、材料类型分别记录；openclaw 等客户端名称仅用于审计，不能影响授权。

阶段记录至少包含 jobId、stepKey、输入指纹、版本、状态、产物引用、尝试次数和错误。固定阶段：

1. 输入确认。
2. 大纲生成或 PPT 页面导入。
3. 按场景生成内容。
4. 按页生成讲稿与动作。
5. TTS/媒体生成。
6. 校验并提交课程。

PPT 增强直接使用原页面，跳过重新生成视觉内容。完成步骤可复用；上游输入发生变化时，其依赖步骤失效。已成功任务需要调整时创建关联新任务，禁止改写历史结果。

记录模型标识、提示词/解析器版本和非秘密参数；密钥执行时读取服务端配置。配置不可用时显式失败，不悄悄换模型继续后半门课。

### 4.2 执行权与重试

领取任务时原子递增执行代次。续租、进度、阶段写入、失败及最终提交均验证当前代次、状态和有效租约。旧 worker 丢失租约后即使恢复，也不能覆盖新执行者。

状态为 queued、running、succeeded、failed、cancelled、conflict。可重试失败返回 queued 并设置 run_after；耗尽次数进入 failed。终态不可被迟到更新覆盖。人工重试建立关联新任务，可复用匹配指纹的产物。

租约使用数据库时间。取消先记录请求，执行器尽力 Abort；提交事务再次检查。取消和提交按数据库锁顺序决定胜者；已成功提交不能报告已撤销。

保证同一幂等请求只产生一次业务提交，不承诺外部模型只调用或计费一次。模型返回但产物尚未保存时崩溃，允许重做该步骤，并记录用量风险。限制 SDK、步骤及整任务多层重试叠加。

### 4.3 幂等及课程最终提交

幂等域：owner + operation + Idempotency-Key。相同 key/相同规范化请求返回原任务；不同内容返回 409。凭证轮换不改变 owner 幂等域。重放仍检查当前 scope、用户和资源权限。

创建任务时固定 courseId；增强任务绑定 sourceRevision。阶段产物保存在任务工作区，未完成内容不作为完整课程公开。

同一 PostgreSQL 连接与事务内：

1. 锁定任务，验证执行代次、有效租约、取消与当前权限。
2. 校验必需阶段与资产就绪。
3. 创建 app.courses，或按 contentRevision 条件更新已有草稿。
4. 绑定资产、写结果 revision、将任务标记 succeeded。
5. 提交事务。

模型调用、COS 上传全部在事务外。响应丢失后重放返回同课程和 revision。版本冲突保留教师修改及候选产物，任务进入 conflict；删课、禁用或降权按明确规则失败。

正式链接由可信应用域名配置生成，不依赖任意转发 Host。生成成功表示课程已正式保存且可按权限访问，不能只表示本机文件落盘。

### 4.4 质量与发布

任务状态与质量分离。succeeded 可有 complete 或 needs_review，必须返回 warnings、失败页和缺失能力。必需阶段失败进入 failed，并保留已完成产物。

用户选择旁白时，旁白默认是必需能力；失败不能标完整成功。可选图片失败可形成有警告草稿。原 PPT 缺页不得静默跳过。

成功生成只创建或更新草稿；发布、学员分配继续沿用已有流程与快照。课程链接不等于分享权限，修改草稿不改变已发布学习快照。

## 5. 资产与 PPT 解析

来源文件进入 COS 后确认归属、实际大小、类型、内容指纹并冻结引用；不只信任客户端 MIME。沿用 course_assets，明确“上传已确认”和“绑定课程”两个独立语义，避免将未绑定材料误当不可用。

持久内容使用资产 ID/受控应用引用，禁止 blob 或过期签名 URL。上传 URL 可包含对象路径，但业务接口不依赖其结构。确认后必须避免客户端覆盖已引用对象。

COS 与数据库不能原子提交。产物按任务/阶段与内容指纹识别复用；不覆盖已绑定对象。孤儿产物经宽限期和引用复查后由清理任务回收。

A2 用同一组样本验证浏览器、Node、隔离 Chromium 的路径与资源峰值。网页端先复用现有 importer；外部上传必须具有已验证的服务器执行环境。视频 renderer 仅提供参考，不默认共用接口或扩大网络权限。

统一 ImportResult 包含 schemaVersion、来源 hash、解析器版本、页码、稳定 scene/element ID、备注、资产与警告。支持元素保持可编辑；不支持元素在有可信渲染能力时降级图片并标注不可编辑，否则显式报不支持。不能承诺复杂 PPT 全元素保真。

讲师备注优先作为讲稿来源，区分原文与 AI 补充。首版不含旧 .ppt、全动画保真和品牌 StyleSkill 提取。

约束 PPTX 压缩包大小、解压总量、条目数、解析时间和内存，关闭非必要外部资源访问。浏览器关闭后从已存来源重新解析；浏览器解析过程不承诺逐步断点恢复。

## 6. 对外 API 与教师委托令牌

首版使用代表教师的个人令牌；课程 owner 是教师，credential 是调用审计身份。
有效权限 = scope ∩ 用户当前权限 ∩ 资源权限。

先交付文本生成、本人任务查询/取消和结果链接，一个真实 Skill 客户端。令牌一次显示、哈希存储、可到期/撤销。请求、worker 开始执行及最终提交前重新检查禁用和降权。

撤销令牌阻止该令牌关联的未完成任务继续提交；教师仍能通过 session 查看保留结果。机器返回课程链接仍要求正常登录与课程权限。

首版采用轮询、每人及全局在途数量限制、限速、重试预算和用量审计。全文材料、令牌不进入日志。上传 scope 和第二客户端在 F 批次增加。Webhook、独立机器人账号、复杂配额界面后置。

## 8. Gate、资源与回滚

开发 Gate：确认代码基线和在制改动归属，记录相关测试基线，冻结任务/恢复/提交契约，可在隔离环境实施。
生产 Gate：实际部署与迁移版本、恢复演练、容量、授权及故障注入测试、桌面移动端业务闭环全部有证据。文档更新或工作树干净不代表通过。

新任务只写 PostgreSQL。切换前停止旧入口接单，排空或明确结束旧任务；旧 JSON 可只读，不双写同一个任务，也不允许两套 runner 消费同任务。

回滚关闭新增入口、暂停领取，保留新表和产物，使用理解新 schema 的兼容版本；不能回到 JSON runner 消费新任务。增量 migration 保持向前兼容，破坏性清理另期执行。

原网页分场景流程保持兼容，不作为首批必须全切换的条件。新 worker、视频渲染、PPT 解析共同使用主机预算，测量 CPU/RAM/磁盘/带宽/PG 连接数后设全局和分类并发，避免独立容器上限合计超过主机容量。

## 10. 排期与完成定义

撤回旧版首批 3–5 周、总体 17–23 周的承诺。A 预计 2–4 个工作日，仅作计划假设；其后根据解析环境、阶段拆分和生产基线估算 B–F，给出最可能工期与风险余量。
