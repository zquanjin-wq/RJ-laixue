## 1. 现状核对（来自 outbox.ts dequeueOne 409 分支，行 251-282）

```ts
// 行 251：进入 409 分支
if (resp.status === 409) {
  const ec = await extractErrorCode(resp);

  // 行 253-268：create CONFLICT → 幂等成功（维持不变）
  const isCreateConflictOk = claimed.op === 'create_session' && ec === 'CONFLICT';
  // ... succeededEntries 落凭据，telemetry 'outbox_create_conflict_ok'

  // 行 269-279：IDEMPOTENCY_CONFLICT 或 非 create 空 errorCode → 死信
  if (isIdempotentConflict || (ec === '' && claimed.op !== 'create_session')) {
    // cascadeMarkDeadInTx → status='dead'
    // telemetry reason='idempotency_conflict'
  }

  // 行 281：未知 409 → throw → attempts++ → 退避重试
  throw new Error(`HTTP 409 errorCode=${ec || 'unknown'}`);
}
```

**事实**：`INACTIVE_SESSION` 当前落在"未知 409"分支 → throw → attempts+1 → 退避 → 最多 7 次后 dead（reason='max_retries'）。这不是永久不可恢复的判断——每次退避浪费请求且 dead 原因失真。

## 2. 分类判定表

| errorCode | op | 分类 | 行为 |
|-----------|----|:--:|------|
| `CONFLICT` | create_session | 幂等成功 | 落 succeededEntries，return true |
| `IDEMPOTENCY_CONFLICT` | 任意 | 永久 dead | cascadeMarkDeadInTx，reason=`IDEMPOTENCY_CONFLICT_permanent` |
| `INACTIVE_SESSION` | **非** create_session | 永久 dead | cascadeMarkDeadInTx，reason=`INACTIVE_SESSION_permanent` |
| `INACTIVE_SESSION` | create_session | 未知 409 | throw → 退避重试（create 不应出现此错误码） |
| 空字符串 `''` | 非 create_session | 死信（旧格式兜底） | cascadeMarkDeadInTx |
| 空字符串 `''` | create_session | 未知 409 | throw |
| 其他 | 任意 | 未知 409 | throw → 退避重试 |

**判定顺序**（按行）：
1. 201/200 → 成功
2. 404 → handle404 或退避
3. 409 → extractErrorCode
   a. create CONFLICT → 幂等
   b. **INACTIVE_SESSION + 非 create → dead（新增）**
   c. IDEMPOTENCY_CONFLICT / 空 errorCode 死信 → dead
   d. 其他 → 未知 409 throw

### 3.2 cascadeMarkDeadInTx 修订

```ts
async function cascadeMarkDeadInTx(
  entryId: string,
  reason: string = 'CASCADE_DEAD',  // ← 参数化
): Promise<number> {
  let cascaded = 0;
  const queue: Array<{ id: string; reason: string }> = [{ id: entryId, reason }];
  while (queue.length > 0) {
    const { id, reason: r } = queue.shift()!;
    await db.runtimeOutbox.update(id, {
      status: 'dead',
      leaseOwner: undefined,
      leaseUntil: undefined,
      deadReason: r,
      deadAt: new Date().toISOString(),
    });
    cascaded++;
    const deps = await db.runtimeOutbox.where('dependsOnEntryId').equals(id).toArray();
    for (const dep of deps) queue.push({ id: dep.id, reason: 'CASCADE_DEAD' });
  }
  return cascaded;
}
```

### 3.3 409 分支新增

在 create CONFLICT 幂等之后、IDEMPOTENCY_CONFLICT/空死信之前插入：

```ts
// line ~269: 新增 INACTIVE_SESSION 分类
if (ec === 'INACTIVE_SESSION') {
  if (claimed.op !== 'create_session') {
    const applied = await db.transaction('rw', db.runtimeOutbox, async () => {
      const fresh = await db.runtimeOutbox.get(claimed.id);
      if (!fresh || fresh.status !== 'sending' || fresh.leaseOwner !== claimed.leaseOwner) return false;
      await cascadeMarkDeadInTx(claimed.id, 'INACTIVE_SESSION_permanent');
      return true;
    });
    if (applied) {
      reportTelemetry('outbox_dead', {
        entryId: claimed.id,
        reason: 'inactive_session',
        sessionId: claimed.sessionId,
      });
    }
    return true;
  }
  // create_session + INACTIVE_SESSION → 不可能路径，按未知 409 继续退避
}

// line ~274: 既有 IDEMPOTENCY_CONFLICT / 空死信分支（v0.1 补充 2 拆分独立值）
if (isIdempotentConflict) {
  const applied = await db.transaction('rw', db.runtimeOutbox, async () => {
    const fresh = await db.runtimeOutbox.get(claimed.id);
    if (!fresh || fresh.status !== 'sending' || fresh.leaseOwner !== claimed.leaseOwner) return false;
    await cascadeMarkDeadInTx(claimed.id, 'IDEMPOTENCY_CONFLICT_permanent');
    return true;
  });
  if (applied) reportTelemetry('outbox_dead', { entryId: claimed.id, reason: 'idempotency_conflict' });
  return true;
}

if (ec === '' && claimed.op !== 'create_session') {
  const applied = await db.transaction('rw', db.runtimeOutbox, async () => {
    const fresh = await db.runtimeOutbox.get(claimed.id);
    if (!fresh || fresh.status !== 'sending' || fresh.leaseOwner !== claimed.leaseOwner) return false;
    await cascadeMarkDeadInTx(claimed.id, 'UNKNOWN_409_permanent');
    return true;
  });
  if (applied) reportTelemetry('outbox_dead', { entryId: claimed.id, reason: 'unknown_409' });
  return true;
}
```

### 3.4 现有的 cascadeMarkDeadInTx 调用点修订

| 调用点 | 原代码 | 修订 | deadReason 字段值 |
|--------|--------|------|-------------------|
| dequeueOne 依赖 dead/superseded（行 184-186）| `cascadeMarkDeadInTx(entry.id)` | **不改**——保持现状，默认 reason='CASCADE_DEAD'；telemetry 走既有 `outbox_dependency_dead` | `CASCADE_DEAD` |
| dequeueOne 依赖凭据丢失（行 193）| `cascadeMarkDeadInTx(entry.id)` | **不改**——保持现状，默认 reason='CASCADE_DEAD'；telemetry 走既有 `outbox_dependency_lost` | `CASCADE_DEAD` |
| IDEMPOTENCY_CONFLICT 递归 dead（行 274）| `cascadeMarkDeadInTx(claimed.id)` | `cascadeMarkDeadInTx(claimed.id, 'IDEMPOTENCY_CONFLICT_permanent')` | `IDEMPOTENCY_CONFLICT_permanent` |
| 空 errorCode 非 create 死信（行 274 同级）| `cascadeMarkDeadInTx(claimed.id)` | `cascadeMarkDeadInTx(claimed.id, 'UNKNOWN_409_permanent')`（v0.1 补充 2）| `UNKNOWN_409_permanent` |
| max_retries dead（行 293）| `cascadeMarkDeadInTx(claimed.id)` | `cascadeMarkDeadInTx(claimed.id, 'max_retries')` | `max_retries` |
| INACTIVE_SESSION dead（行 269 新增）| — | `cascadeMarkDeadInTx(claimed.id, 'INACTIVE_SESSION_permanent')` | `INACTIVE_SESSION_permanent` |

**注意**：行 184/193 两处调用点本卡不动——它们的 commit 已在 R3.0 签字关闭。此处仅如实记录它们产生的 `CASCADE_DEAD` 字段值，避免后续读表误以为 CASCADE_DEAD 只来自级联后继。

### 3.5 telemetry reason 映射

| deadReason 字段值 | telemetry `reason` 上报值 | 来源 | 说明 |
|-------------------|--------------------------|------|------|
| `INACTIVE_SESSION_permanent` | `inactive_session` | 409 INACTIVE_SESSION（本次新增） | 本次新增 |
| `IDEMPOTENCY_CONFLICT_permanent` | `idempotency_conflict` | 409 IDEMPOTENCY_CONFLICT | 维持既有 |
| `UNKNOWN_409_permanent` | `unknown_409` | 空 errorCode 409 非 create（v0.1 补充 2） | 本次新增独立值，区分于 IDEMPOTENCY_CONFLICT |
| `CASCADE_DEAD` | `cascade_dead` | 级联后继 + 行 184/193 根 entry | 既有路径默认值；行 184/193 调用点不改 |
| `max_retries` | `max_retries` | 重试耗尽（attempts≥DEAD_AFTER_ATTEMPTS） | 维持既有 |

**边界**：deadReason/telemetry 字段落 `RuntimeOutboxEntry.deadReason`（Dexie），但**不上报** `client-diagnostics`（等 R3.1a diagnostics 契约卡）。

## 4. 门禁

| # | 场景 | 断言 |
|---|------|------|
| C1-1 | append_record 收到 `{ errorCode: 'INACTIVE_SESSION', error: '...' }` 409 | entry.status='dead'，deadReason='INACTIVE_SESSION_permanent'，attempts 不增（=0 或原值），无退避调度重试 |
| C1-2 | append 有 `dependsOnEntryId`→status 后继 | status 后继 cascade dead，deadReason='CASCADE_DEAD' |
| C1-3 | set_status 收到 409 INACTIVE_SESSION | 同 C1-1 |
| C1-4 | create_session 收到 409 INACTIVE_SESSION（人工构造异常 resp） | 不 dead，退避重试（attempts++） |
| C1-5 | 空 errorCode 409，非 create | 死信兜底，deadReason='UNKNOWN_409_permanent'（空 errorCode 不套用 IDEMPOTENCY_CONFLICT 语义） |
| C1-6 | 409 IDEMPOTENCY_CONFLICT | 递归 dead，deadReason='IDEMPOTENCY_CONFLICT_permanent' |
| C1-7 | 过期 lease 的 409 INACTIVE_SESSION（leaseOwner 不匹配） | CAS 拒绝 → 不落 dead，不影响有效 lease 的条目 |
