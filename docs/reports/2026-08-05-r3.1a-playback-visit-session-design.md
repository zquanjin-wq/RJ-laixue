## 1. 核心契约（v0.5 修订）

### 1.1 模型命名（沿用）

"new session per completed playback cycle"

### 1.2 cycle 定义（沿用）

- 起点：本次 cycle 第一次有效持久化
- 终点：set_status completed 成功凭据落 succeededEntries

### 1.3 visitId 全局唯一（v0.5 修订）

**统一**使用 `generateHexId(16)`（v0.4 已提议），v0.5 删除所有 `crypto.randomUUID()` 用法。

```ts
function generateHexId(byteLen: number): string {
  const buf = new Uint8Array(byteLen);
  crypto.getRandomValues(buf);
  return Array.from(buf, (b) => b.toString(16).padStart(2, '0')).join('');
}

// 全部入口
const visitId = generateHexId(16);  // 32 hex chars, no hyphens
```

### 1.4 tabOwner 强隔离：异步 BroadcastChannel 碰撞协议（v0.5.1 勘误）

**v0.5 漏洞**：
1. `sessionStorage` 已有 ID 时直接返回，复制页永不进入碰撞检测
2. `while (Date.now() - start < 100)` 阻塞事件循环，`onmessage` 无法执行

**修正**：

```ts
const INSTANCE_ID = generateHexId(16);

// ── 异步 claim：禁止 busy-wait ──
async function claimTabOwnerId(): Promise<string> {
  const KEY = 'r3:tab:owner-id';
  const existing = sessionStorage.getItem(KEY);

  // 1. 若已有 ID，仍需异步探测是否被占用
  if (existing) {
    const free = await probeOwnerId(existing);
    if (!free) {
      // 占用 → 清除（旧 document 可能 crash 后残留，新 instance 必须重试）
      sessionStorage.removeItem(KEY);
    } else {
      return existing;
    }
  }

  // 2. 从 4 个候选选一个未被占用的
  const candidates = Array.from({ length: 4 }, () => generateHexId(16));
  for (const candidate of candidates) {
    const free = await probeOwnerId(candidate);
    if (free) {
      sessionStorage.setItem(KEY, candidate);
      return candidate;
    }
  }
  throw new Error('Failed to claim tabOwnerId after 4 attempts');
}

// ── 异步探测：setTimeout + Promise ──
async function probeOwnerId(ownerId: string): Promise<boolean> {
  return new Promise<boolean>((resolve) => {
    const channel = new BroadcastChannel(`r3:tab:claim:${ownerId}`);
    let occupied = false;
    let settled = false;

    const done = (free: boolean) => {
      if (settled) return;
      settled = true;
      channel.close();
      resolve(free);
    };

    channel.onmessage = (event) => {
      if (event.data?.type === 'ping') {
        // 收到探测 → 自己是原 occupant → 回应 occupied
        // instanceId 字典序 tiebreak：避免双方同时放弃
        if (event.data.from < INSTANCE_ID ||
            (event.data.from === INSTANCE_ID && event.data.priority ? true : false)) {
          // 对方字典序更小 → 自己让步
          occupied = true;
        } else {
          // 自己保留 → 回应 occupied 给对方
          channel.postMessage({ type: 'occupied', from: INSTANCE_ID });
        }
      } else if (event.data?.type === 'occupied') {
        occupied = true;
      }
    };

    // 发送 ping
    channel.postMessage({ type: 'ping', from: INSTANCE_ID });

    // 异步 etc：150ms 无 occupied → claim 成功
    setTimeout(() => done(!occupied), 150);
  });
}
```

**关键修正**：
- `claimTabOwnerId()` 改为 `async`，返回 `Promise<string>`
- **即使 sessionStorage 已有 ID，也必须 `probeOwnerId`**
- busy-wait `while` 替换为 `setTimeout + Promise`
- **instanceId 字典序 tiebreak**：词序更小的 ID 保留，避免双方同时认为自己被占用
- claimOrReuseVisitInTx 改为 `claimOrReuseVisitInTx(stageId, await getTabOwnerId())`

### 1.8 create/completed 身份 + complete preflight（v0.5.1 勘误）

**v0.5 漏洞**：
1. 新 append 已入队后才检查已有 completed，eventId 相同时新 append 仍会发送 `→ INACTIVE_SESSION`
2. `where('dependsOnEntryId').equals(completedStatusEntryId)` 方向反了——真实关系是 `status.dependsOnEntryId = appendId`

**修正**：preflight **在写 state/入队 append 之前**完成。依赖方向修正为 `status.dependsOnEntryId`。

```ts
// ── complete preflight（在 persistSnapshotWithComplete 事务最开头）──
async function completePreflightInTx(
  visit: PlaybackVisit,
  snapshot: { eventId: string; completed?: boolean },
): Promise<'new' | { revisit: true; appendId: string; statusId: string }> {
  if (!snapshot.completed || !visit.completedStatusEntryId) return 'new';

  // 1. 读 status entry
  const statusEntry = await db.runtimeOutbox.get(visit.completedStatusEntryId);
  if (!statusEntry) {
    // status 不在 outbox ——— 可能已在 succeededEntries
    const cred = await db.succeededEntries.get(visit.completedStatusEntryId);
    if (cred) {
      // completed 凭据成立 → 当前 cycle 已结束 → 启动新 cycle
      return 'new';
    }
    // 不在 outbox 也不在 succeeded → 状态异常，但重新入队
    return 'new';
  }

  // 2. status.dependsOnEntryId = append 的 entry ID
  const appendEntry = await db.runtimeOutbox.get(statusEntry.dependsOnEntryId);
  if (!appendEntry) return 'new';  // append 已 send → 不阻碍

  // 3. 比较 eventId
  const appendEventId = (appendEntry.body as any)?.id?.split(':').pop();
  if (appendEventId === snapshot.eventId) {
    // eventId 一致 → 幂等返回（零新入队）
    return { revisit: true, appendId: appendEntry.id, statusId: statusEntry.id };
  }

  // 4. eventId 不一致 → 拒绝（原链未完成）
  throw new SnapshotEventMismatchError(visit.visitId, snapshot.eventId);
}
```

**persistSnapshotWithComplete 流程修订**（preflight 在最前面）：

```ts
async function persistSnapshotWithComplete(stageId, snapshot) {
  const ownerId = await claimTabOwnerId();  // v0.5.1：async

  return db.transaction(...4 tables..., async () => {
    const visit = await claimOrReuseVisitInTx(stageId, ownerId);

    // ★ preflight（必须在写 state / 入队 before append）
    if (snapshot.completed) {
      const pre = await completePreflightInTx(visit, snapshot);
      if (pre !== 'new') {
        // 幂等返回（revisit:true）——零新入队，调用方无感
        return pre;
      }
      // new: 正常入队（新 cycle 或 重新入队）
    }

    // ... 其余：写 state → ensure create → append → set_status（同事务）
  });
}
```

**关键修正**：
- preflight **在 state 写 + append 入队之前**执行，杜绝 eventId 相同但新 append 重复入队
- 依赖方向：`status.dependsOnEntryId = appendEntryId`（不是反向）
- eventId 一致 → 幂等返回既有 IDs（**零新入队**）
- eventId 不一致且 status 未成功 → `SnapshotEventMismatchError`（不设新链）
- status 已 succeed → 启动新 cycle（正常的 cycle 切换）
- 所有行为在同一 Dexie 事务内原子完成

### 2.2 claimOrReuseVisitInTx（v0.5 关键修订）

**问题**：v0.4 claimOrReuseVisit 是独立事务，嵌套事务不合法。

**解决**：拆为 `claimOrReuseVisitInTx`，仅在当前持久化事务上下文中运行（不嵌套 db.transaction）。

```ts
// 假设外部已经开事务 'rw', [db.playbackVisits, db.playbackVisitStates,
//                              db.runtimeOutbox, db.runtimeChainHeads]
async function claimOrReuseVisitInTx(stageId: string, tabOwnerId: string):
  Promise<PlaybackVisit> {
  // 1. 同 (stageId, tabOwnerId) active visit？
  const mine = await db.playbackVisits
    .where('[tabOwnerId+stageId]').equals([tabOwnerId, stageId])
    .filter(v => v.status === 'active')
    .first();
  if (mine) return mine;

  // 2. 不存在 → 创建新 visit
  const visitId = generateHexId(16);
  const sessionId = `pb:${stageId}:${visitId}`;
  const now = new Date().toISOString();
  const visit: PlaybackVisit = {
    visitId, stageId, tabOwnerId, sessionId,
    status: 'active', createdAt: now,
  };
  await db.playbackVisits.add(visit);
  return visit;
}
```

### 2.5 persistSnapshotWithComplete 完整流程（v0.5 最终）

```ts
async function persistSnapshotWithComplete(stageId, snapshot) {
  const tabOwnerId = await claimTabOwnerId();  // v0.5.1
  
  return db.transaction(
    'rw',
    [db.playbackVisits, db.playbackVisitStates, db.runtimeOutbox, db.runtimeChainHeads],
    async () => {
      const visit = await claimOrReuseVisitInTx(stageId, tabOwnerId);
      
      // 1. 写 visit-specific state
      await db.playbackVisitStates.put({
        visitId: visit.visitId,
        stageId,
        sceneIndex: snapshot.sceneIndex,
        actionIndex: snapshot.actionIndex,
        consumedDiscussions: snapshot.consumedDiscussions ?? [],
        sceneId: snapshot.sceneId,
        capturedAt: snapshot.capturedAt,
        updatedAt: Date.now(),
        completed: snapshot.completed,
        runtimeShadowEventId: snapshot.eventId,
        shadowPending: { eventId: snapshot.eventId, capturedAt: snapshot.capturedAt },
      });
      
      // 2. ensure create entry（仅当 visit.createEntryId 不存在）
      let prevId: string | undefined = visit.createEntryId;
      if (!prevId) {
        const createEntryId = await _qEnqueue({
          sessionId: visit.sessionId, op: 'create_session',
          semanticKey: `pb:create:${visit.sessionId}`,
          body: { id: visit.sessionId, kind: 'playback', stageId,
                  status: 'active', createdAt: snapshot.capturedAt },
        });
        prevId = createEntryId;
        await db.playbackVisits.update(visit.visitId, { createEntryId });
      }
      
      // 3. append
      const appendId = await _qEnqueue({
        sessionId: visit.sessionId, op: 'append_record',
        semanticKey: `pb:append:${visit.sessionId}:${snapshot.eventId}`,
        body: { id: `${visit.sessionId}:${snapshot.eventId}`,
                createdAt: snapshot.capturedAt, sceneId: snapshot.sceneId,
                payload: { v: 1, sceneIndex: snapshot.sceneIndex,
                           actionIndex: snapshot.actionIndex,
                           consumedDiscussions: snapshot.consumedDiscussions ?? [],
                           capturedAt: snapshot.capturedAt } },
      }, prevId);
      
      // 4. completed set_status（CAS 行为见 §1.8）
      let statusId: string | undefined;
      if (snapshot.completed) {
        statusId = await enqueueCompleteWithCASInTx(visit, snapshot, appendId);
      }
      
      return { visitId: visit.visitId, appendId, statusId };
    }
  );
}
```

## 3. Legacy/Outbox 终结（v0.5 修订）

### 3.1 409 响应格式（v0.5 修订）

**问题**：v0.4 提议复用 `extractErrorCode`，但它**未 export**且入参是 Response。

**解决**：在 R3.0 中央响应处理中扩展 INACTIVE_SESSION 分类（**独立设计卡**）。

R3.1a **不直接消费 Response**。中央 dequeueOne 处理后通过 entry 状态转换表达：
- `errorCode === 'INACTIVE_SESSION'` → outbox 永久 dead，reason='INACTIVE_SESSION_permanent'

R3.1a 不引入新的 Response 解析；R3.0 中央扩展是单独签字卡。

**Adoption 规则**（v0.5.1 勘误：修正索引 + 接通调用链）：

**v0.5 漏洞**：
1. `where('stageId')` 没有对应索引 → 运行时错误
2. `claimOrReuseVisitInTx()` 未调用 `adoptLegacyVisitInTx()`——adoption 是孤立伪代码

**修正**：使用 `[stageId+status]` 复合索引；adoption 成为 `claimOrReuseVisitInTx` 的**第一步**。

```ts
// ── 在 claimOrReuseVisitInTx 开头 ──
async function claimOrReuseVisitInTx(stageId: string, tabOwnerId: string):
  Promise<PlaybackVisit> {
  // 0. 先查 legacy adoption（仅当升级后首次）
  const legacyVisit = await db.playbackVisits
    .where('[stageId+status]').equals([stageId, 'active'])
    .filter(v => v.visitId === `legacy-${stageId}`)
    .first();
  if (legacyVisit?.isLegacyAdopted) {
    await db.playbackVisits.update(legacyVisit.visitId, {
      tabOwnerId,
      isLegacyAdopted: undefined,  // 清除标记
    });
    return legacyVisit;
  }

  // 1. 同 (stageId, tabOwnerId) active visit？（使用 [tabOwnerId+stageId] 索引）
  const mine = await db.playbackVisits
    .where('[tabOwnerId+stageId]').equals([tabOwnerId, stageId])
    .filter(v => v.status === 'active')
    .first();
  if (mine) return mine;

  // 2. 创建新 visit（正常路径）
  const visitId = generateHexId(16);
  const sessionId = `pb:${stageId}:${visitId}`;
  const visit: PlaybackVisit = {
    visitId, stageId, tabOwnerId, sessionId,
    status: 'active', createdAt: new Date().toISOString(),
  };
  await db.playbackVisits.add(visit);
  return visit;
}
```

**关键修正**：
- `where('[stageId+status]').equals([stageId, 'active'])` —— 使用已建立的复合索引
- legacy adoption 成为 `claimOrReuseVisitInTx` 第一步（消除孤立调用）
- adoption 仅在匹配 `legacy-<stageId>` 且 `isLegacyAdopted=true` 时生效
- legacy 完成后创建正常新 visit（后续调用不再走 adoption）

**关键不变量**：
- legacy visit sessionId = `pb:<stageId>`（与旧 outbox 一致）
- 旧 outbox 条目 sessionId 不变
- legacy visit 通过 `adoptLegacyVisitInTx` 被当前 tab 接管
- 不接管也不创建 → 进入新 visit 路径
