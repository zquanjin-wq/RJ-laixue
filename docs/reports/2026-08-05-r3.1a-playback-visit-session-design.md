## 1. 核心契约（v0.5 修订）

### 1.1 模型命名（沿用）

### 1.3 visitId 全局唯一（v0.5 修订）

**统一**使用 `generateHexId(16)`（v0.4 已提议），v0.5 删除所有 `crypto.randomUUID()` 用法。

```ts
function generateHexId(byteLen: number): string {
  const buf = new Uint8Array(byteLen);
  crypto.getRandomValues(buf);
  return Array.from(buf, (b) => b.toString(16).padStart(2, '0')).join('');
}

// 全部入口
const visitId = generateHexId(16);  // 32 hex chars, no hyphens
```

### 1.4 tabOwner 强隔离：Holder 持续监听 + 让出协议（v0.5.2 勘误）

**v0.5.1 漏洞**：`probeOwnerId` 完成即 `channel.close()`，claim 后 holder 不再应答 ping。复制页的探测在 150ms 后 **也**claim 成功，两 tab 共用同一 ownerId。

**修正**：holder **持续持有频道并监听**，直到 document 销毁；出让语义基于 instanceId 字典序。

```ts
const INSTANCE_ID = generateHexId(16);
let currentOwnerId: string | null = null;
let holderChannel: BroadcastChannel | null = null;

// ── 启动 holder 监听 ──
function startHolderListener(ownerId: string): void {
  const channel = new BroadcastChannel(`r3:tab:claim:${ownerId}`);
  holderChannel = channel;

  channel.onmessage = (event) => {
    if (event.data?.type !== 'ping') return;
    const pingerId = event.data.from;

    // InstanceId 字典序 tiebreak：更小的一方保留 owner
    if (pingerId < INSTANCE_ID) {
      // 对方字典序更小 → 我方让出
      channel.close();
      holderChannel = null;
      currentOwnerId = null;
      sessionStorage.removeItem('r3:tab:owner-id');
    } else {
      // 我方保留 → 回应 occupied
      channel.postMessage({ type: 'occupied', from: INSTANCE_ID });
    }
  };
}

// ── 异步探测：setTimeout + Promise ──
async function probeOwnerId(ownerId: string): Promise<boolean> {
  return new Promise<boolean>((resolve) => {
    const channel = new BroadcastChannel(`r3:tab:claim:${ownerId}`);
    let occupied = false;
    let settled = false;

    const done = (free: boolean) => {
      if (settled) return; settled = true; channel.close(); resolve(free);
    };

    channel.onmessage = (event) => {
      if (event.data?.type === 'occupied') occupied = true;
    };

    channel.postMessage({ type: 'ping', from: INSTANCE_ID });
    setTimeout(() => done(!occupied), 150);
  });
}

// ── 异步 claim ──
async function claimTabOwnerId(): Promise<string> {
  const KEY = 'r3:tab:owner-id';
  const existing = sessionStorage.getItem(KEY);

  // 1. 已有 ID → 异步探测占用——即使持有也必须 ping
  if (existing) {
    const free = await probeOwnerId(existing);
    if (free) {
      currentOwnerId = existing;
      startHolderListener(existing);
      return existing;
    }
    // 已被占用 → 清除并继续候选
    sessionStorage.removeItem(KEY);
  }

  // 2. 候选轮换
  const candidates = Array.from({ length: 4 }, () => generateHexId(16));
  for (const candidate of candidates) {
    const free = await probeOwnerId(candidate);
    if (free) {
      sessionStorage.setItem(KEY, candidate);
      currentOwnerId = candidate;
      startHolderListener(candidate);
      return candidate;
    }
  }
  throw new Error('Failed to claim tabOwnerId after 4 attempts');
}

// ── document 卸载时清理 ──
if (typeof window !== 'undefined') {
  window.addEventListener('beforeunload', () => {
    holderChannel?.close();
    holderChannel = null;
  });
}
```

**让出后行为**：`currentOwnerId = null` → 下一次 `persistSnapshotWithComplete()` 调用时 `claimTabOwnerId()` 重新竞争新 owner，旧 visit 由 outbox 继续排空（不丢数据）。

**关键修正**：
- `startHolderListener` 在 claim 后启动，**持续监听直到 document 销毁**
- holder 收到 ping 时稳定字典序 tiebreak（删除 v0.5.1 无意义的 `from === INSTANCE_ID` 分支）
- holder 让出后不删除旧 outbox（`currentOwnerId = null` 只影响下次 visit 选择）
- `beforeunload` 关闭频道- `claimTabOwnerId()` 改为 `async`，返回 `Promise<string>`
- **即使 sessionStorage 已有 ID，也必须 `probeOwnerId`**
- busy-wait `while` 替换为 `setTimeout + Promise`
- **instanceId 字典序 tiebreak**：词序更小的 ID 保留，避免双方同时认为自己被占用
- claimOrReuseVisitInTx 改为 `claimOrReuseVisitInTx(stageId, await getTabOwnerId())`

### 1.8 create/completed 身份 + complete preflight（v0.5.2 勘误）

**v0.5.1 漏洞及澄清**：

| # | 场景 | v0.5.1 行为 | v0.5.2 修正 |
|---|------|-----------|----------|
| A | status 凭据已有→`return 'new'`→同一 completed visit 出 append→409 | 漏切 cycle | 凭据成立→`VisitCycleCompletedError`→调用方换新 visit |
| B | append 已发、status 仍在 outbox→`return 'new'`→新 append 进链（409） | 放行 | 返回幂等（revisit），不建新 append |
| C | `completedStatusEntryId` 存在但 `completed=false`（普通快照）→`return 'new'`→append 入 completed session（409） | 放行 | 同 A：凭据成立→强制 cycle 切换 |

**统一修正**（preflight 在 state 写 + append 入队前）：

```ts
async function completePreflightInTx(
  visit: PlaybackVisit,
  snapshot: { eventId: string; completed?: boolean },
): Promise<
  | { action: 'idempotent'; appendId: string; statusId: string }  // 零新入队
  | { action: 'cycle_completed' }                                   // 调用方换 visit
  | { action: 'proceed' }                                           // 正常入队
> {
  // ═══ 公理：completed 凭据成立 → 不得 append ─────
  if (visit.completedStatusEntryId) {
    const cred = await db.succeededEntries.get(visit.completedStatusEntryId);
    if (cred) {
      // 凭据成立 → 强制 cycle 切换（覆盖澄清 A、C）
      return { action: 'cycle_completed' };
    }
  }

  // ═══ snapshot 非 completed → 正常入队（不介入）─────
  if (!snapshot.completed || !visit.completedStatusEntryId) {
    return { action: 'proceed' };
  }

  // ═══ status 已入队、未发送 — 比较 eventId ─────
  const statusEntry = await db.runtimeOutbox.get(visit.completedStatusEntryId);
  if (!statusEntry) {
    // 不在 outbox 也不在 succeededEntries → 异常，但重新入队
    return { action: 'proceed' };
  }

  // status.dependsOnEntryId = append entry ID（方向正确）
  const appendEntry = statusEntry.dependsOnEntryId
    ? await db.runtimeOutbox.get(statusEntry.dependsOnEntryId)
    : null;

  if (!appendEntry) {
    // append 已发送、status 仍在 outbox → 不建新 append（覆盖澄清 B）
    // 返回幂等：等 status 完成后自动切 cycle
    return { action: 'idempotent', appendId: statusEntry.dependsOnEntryId!,
             statusId: visit.completedStatusEntryId };
  }

  const appendEventId = (appendEntry.body as any)?.id?.split(':').pop();
  if (appendEventId === snapshot.eventId) {
    // eventId 一致 → 零新入队
    return { action: 'idempotent', appendId: appendEntry.id,
             statusId: visit.completedStatusEntryId };
  }

  // eventId 不一致 → 拒绝（数据完整性）
  throw new SnapshotEventMismatchError(visit.visitId, snapshot.eventId);
}
```

**persistSnapshotWithComplete 流程（调用 preflight）**：

```ts
const pre = await completePreflightInTx(visit, snapshot);
if (pre.action === 'idempotent') {
  return { visitId: visit.visitId, appendId: pre.appendId, statusId: pre.statusId };
}
if (pre.action === 'cycle_completed') {
  throw new VisitCycleCompletedError(visit.visitId); // 调用方 catch → 换 visit 重试
}
// pre.action === 'proceed' → 正常入队
```

**关键修正**：
- preflight 覆盖全部 3 个 edge case（凭据成立、append 已发 status 待定、普通快照 after completed）
- `action: 'idempotent'` 返回既有 IDs，**零新入队**
- `action: 'cycle_completed'` → `VisitCycleCompletedError` → 调用方 `catch` → `persistSnapshotWithComplete` 重试（claim 阶段自会获得新 visit）

### 2.2 claimOrReuseVisitInTx（v0.5 关键修订）

**问题**：v0.4 claimOrReuseVisit 是独立事务，嵌套事务不合法。

**解决**：拆为 `claimOrReuseVisitInTx`，仅在当前持久化事务上下文中运行（不嵌套 db.transaction）。

```ts
// 假设外部已经开事务 'rw', [db.playbackVisits, db.playbackVisitStates,
//                              db.runtimeOutbox, db.runtimeChainHeads]
async function claimOrReuseVisitInTx(stageId: string, tabOwnerId: string):
  Promise<PlaybackVisit> {
  // 1. 同 (stageId, tabOwnerId) active visit？
  const mine = await db.playbackVisits
    .where('[tabOwnerId+stageId]').equals([tabOwnerId, stageId])
    .filter(v => v.status === 'active')
    .first();
  if (mine) return mine;

  // 2. 不存在 → 创建新 visit
  const visitId = generateHexId(16);
  const sessionId = `pb:${stageId}:${visitId}`;
  const now = new Date().toISOString();
  const visit: PlaybackVisit = {
    visitId, stageId, tabOwnerId, sessionId,
    status: 'active', createdAt: now,
  };
  await db.playbackVisits.add(visit);
  return visit;
}
```

  }
);

### 2.5 persistSnapshotWithComplete 完整流程（v0.5 最终）

```ts
async function persistSnapshotWithComplete(stageId, snapshot) {
  const tabOwnerId = await claimTabOwnerId();  // v0.5.1
  
  return db.transaction(
    'rw',
    [db.playbackVisits, db.playbackVisitStates, db.runtimeOutbox, db.runtimeChainHeads],
    async () => {
      const visit = await claimOrReuseVisitInTx(stageId, tabOwnerId);
      
      // 1. 写 visit-specific state
      await db.playbackVisitStates.put({
        visitId: visit.visitId,
        stageId,
        sceneIndex: snapshot.sceneIndex,
        actionIndex: snapshot.actionIndex,
        consumedDiscussions: snapshot.consumedDiscussions ?? [],
        sceneId: snapshot.sceneId,
        capturedAt: snapshot.capturedAt,
        updatedAt: Date.now(),
        completed: snapshot.completed,
        runtimeShadowEventId: snapshot.eventId,
        shadowPending: { eventId: snapshot.eventId, capturedAt: snapshot.capturedAt },
      });
      
      // 2. ensure create entry（仅当 visit.createEntryId 不存在）
      let prevId: string | undefined = visit.createEntryId;
      if (!prevId) {
        const createEntryId = await _qEnqueue({
          sessionId: visit.sessionId, op: 'create_session',
          semanticKey: `pb:create:${visit.sessionId}`,
          body: { id: visit.sessionId, kind: 'playback', stageId,
                  status: 'active', createdAt: snapshot.capturedAt },
        });
        prevId = createEntryId;
        await db.playbackVisits.update(visit.visitId, { createEntryId });
      }
      
      // 3. append
      const appendId = await _qEnqueue({
        sessionId: visit.sessionId, op: 'append_record',
        semanticKey: `pb:append:${visit.sessionId}:${snapshot.eventId}`,
        body: { id: `${visit.sessionId}:${snapshot.eventId}`,
                createdAt: snapshot.capturedAt, sceneId: snapshot.sceneId,
                payload: { v: 1, sceneIndex: snapshot.sceneIndex,
                           actionIndex: snapshot.actionIndex,
                           consumedDiscussions: snapshot.consumedDiscussions ?? [],
                           capturedAt: snapshot.capturedAt } },
      }, prevId);
      
      // 4. completed set_status（CAS 行为见 §1.8）
      let statusId: string | undefined;
      if (snapshot.completed) {
        statusId = await enqueueCompleteWithCASInTx(visit, snapshot, appendId);
      }
      
      return { visitId: visit.visitId, appendId, statusId };
    }
  );
}
```

## 3. Legacy/Outbox 终结（v0.5 修订）

### 3.1 409 响应格式（v0.5 修订）

**问题**：v0.4 提议复用 `extractErrorCode`，但它**未 export**且入参是 Response。

**解决**：在 R3.0 中央响应处理中扩展 INACTIVE_SESSION 分类（**独立设计卡**）。

R3.1a **不直接消费 Response**。中央 dequeueOne 处理后通过 entry 状态转换表达：
- `errorCode === 'INACTIVE_SESSION'` → outbox 永久 dead，reason='INACTIVE_SESSION_permanent'
- `errorCode === 'IDEMPOTENCY_CONFLICT'` → 已签 R3.0 行为：递归 dead，reason='IDEMPOTENCY_CONFLICT_permanent'

R3.1a 不引入新的 Response 解析；R3.0 中央扩展是单独签字卡。

## 4. E2E 门禁（v0.5.2 修订，20 项）

| # | 场景 | 期望 |
|---|------|------|
| 1 | 首次进入课程，播放 3 个场景 | outbox 全部 201，最终 completed 200 |
| 2 | 首笔快照即 completed | create(active)→append→completed 同事务入队 |
| 3 | 同一 tabOwner 完成后再播放 | 新 visitId，同 tabOwnerId |
| 4 | completed PATCH 失败后刷新 | 同 visitId 重试 |
| 5 | F5 刷新（无新动作） | visitId 不变 |
| 6 | 课程中切场景（同 visit） | 同 sessionId，append 201 |
| 7 | 旧 pb:<stageId> 失败条目不阻断新 visit | 新 visit 独立完成 |
| 8 | 同 stage 两标签页并发 | 两独立 tabOwnerId → 两 visit，snapshot 不串 |
| 9 | 刷新后成功条目不复活 | succeededEntries 的 entry 不重发 |
| 10 | outbox 排空 + completedCredentialAt 落 succeededEntries | 下个 cycle 启动 |
| 11 | 关闭浏览器重新打开 | 新 tabOwnerId → 新 visit |
| 12 | 旧 cycle 未完成时新动作 | 不轮换 |
| 13 | 两标签页快照绝不串 visit | playbackVisitStates 按 visitId 隔离 |
| 14 | **复制标签页（opener）BroadcastChannel 碰撞** | 原 ownerId 占用，新 ownerId 通过异步探测检测到并轮换。同时启动时仅一方保留原 owner（字典序 tiebreak）。**holder 先 claim 完成并监听后，第二个 tab 再启动——仍检测到占用并轮换**（v0.5.2 补门禁） |
| 15 | **v17→v18 数据无损迁移** | 旧 playbackState 复制到 visitStates，**session id 保留为 pb:<stageId>** |
| 16 | **重复 complete 幂等返回 + 零新入队** | eventId 一致幂等返回既有 IDs；eventId 不一致且在 status 未成功前拒绝；**重复 complete 后 runtimeOutbox 条目数不增加** |
| 17 | **adoption 查询不抛 Dexie SchemaError** | `[stageId+status]` 复合索引存在，`where('[stageId+status]')` 编译通过 |
| 18 | **两标签页并发 adoption 恰好一个接管** | 两个 claimOrReuseVisitInTx 在同一 stage 上，只有一行 `isLegacyAdopted: undefined` 更新成功，另一个创建新 visit |
| 19 | **completed 无凭据 legacy 不被接管** | `legacy-<stageId>` 行 status='completed'→`where('[stageId+status]').equals(['<stageId>','active'])` 查不到→创建正常新 visit |
| 20 | **接管后 sessionId = pb:\<stageId\>，旧 outbox 不重发** | adoption 更新的 visit.sessionId 与 `runtimeOutbox` 条目一致；succeededEntries 有凭据的条目不重发 |

**20 个场景**，覆盖全部 P0 + adoption。

### 5.2 v17→v18 迁移（保留 legacy session identity）

**关键修正**：v0.4 迁移把 session 改成 `pb:<stageId>:legacy-<stageId>`，会与原 `pb:<stageId>` 服务端 session 分裂。

```ts
await this.version(18).upgrade(async (tx) => {
  // 1. 读旧 playbackState
  const oldRows = await tx.table('playbackState').toArray();
  
  // 2. 创建 legacy visits：sessionId = `pb:<stageId>`（与旧条目完全一致）
  const legacyVisits: PlaybackVisit[] = oldRows.map(row => ({
    visitId: `legacy-${row.stageId}`,  // 显式前缀，仅供本地查找
    stageId: row.stageId,
    tabOwnerId: 'legacy-unknown',
    sessionId: `pb:${row.stageId}`,  // 关键：与旧 outbox session identity 一致
    status: row.completed ? 'completed' : 'active',
    createdAt: new Date(row.updatedAt || Date.now()).toISOString(),
    createdByOwnerAt: new Date(row.updatedAt || Date.now()).toISOString(),
    isLegacyAdopted: true,
    // completedCredentialAt 不可知
  }));
  await tx.table('playbackVisits').bulkAdd(legacyVisits);
  
  // 3. 复制旧 row 到 visitStates（绑定 legacy visit）
  const newStates: PlaybackVisitState[] = oldRows.map(row => ({
    visitId: `legacy-${row.stageId}`,
    stageId: row.stageId,
    sceneIndex: row.sceneIndex,
    actionIndex: row.actionIndex,
    consumedDiscussions: row.consumedDiscussions ?? [],
    sceneId: row.sceneId,
    capturedAt: row.capturedAt,
    updatedAt: row.updatedAt,
    completed: row.completed,
    runtimeShadowEventId: row.runtimeShadowEventId,
    shadowPending: row.shadowPending,
  }));
  await tx.table('playbackVisitStates').bulkAdd(newStates);
  
  // 4. 旧 playbackState 行不删除
});
```

**Adoption 规则**（v0.5.1 勘误：修正索引 + 接通调用链）：

**v0.5 漏洞**：
1. `where('stageId')` 没有对应索引 → 运行时错误
2. `claimOrReuseVisitInTx()` 未调用 `adoptLegacyVisitInTx()`——adoption 是孤立伪代码

**修正**：使用 `[stageId+status]` 复合索引；adoption 成为 `claimOrReuseVisitInTx` 的**第一步**。

```ts
// ── 在 claimOrReuseVisitInTx 开头 ──
async function claimOrReuseVisitInTx(stageId: string, tabOwnerId: string):
  Promise<PlaybackVisit> {
  // 0. 先查 legacy adoption（仅当升级后首次）
  const legacyVisit = await db.playbackVisits
    .where('[stageId+status]').equals([stageId, 'active'])
    .filter(v => v.visitId === `legacy-${stageId}`)
    .first();
  if (legacyVisit?.isLegacyAdopted) {
    await db.playbackVisits.update(legacyVisit.visitId, {
      tabOwnerId,
      isLegacyAdopted: undefined,  // 清除标记
    });
    return legacyVisit;
  }

  // 1. 同 (stageId, tabOwnerId) active visit？（使用 [tabOwnerId+stageId] 索引）
  const mine = await db.playbackVisits
    .where('[tabOwnerId+stageId]').equals([tabOwnerId, stageId])
    .filter(v => v.status === 'active')
    .first();
  if (mine) return mine;

  // 2. 创建新 visit（正常路径）
  const visitId = generateHexId(16);
  const sessionId = `pb:${stageId}:${visitId}`;
  const visit: PlaybackVisit = {
    visitId, stageId, tabOwnerId, sessionId,
    status: 'active', createdAt: new Date().toISOString(),
  };
  await db.playbackVisits.add(visit);
  return visit;
}
```

**关键修正**：
- `where('[stageId+status]').equals([stageId, 'active'])` —— 使用已建立的复合索引
- legacy adoption 成为 `claimOrReuseVisitInTx` 第一步（消除孤立调用）
- adoption 仅在匹配 `legacy-<stageId>` 且 `isLegacyAdopted=true` 时生效
- legacy 完成后创建正常新 visit（后续调用不再走 adoption）

**关键不变量**：
- legacy visit sessionId = `pb:<stageId>`（与旧 outbox 一致）
- 旧 outbox 条目 sessionId 不变
- legacy visit 通过 `adoptLegacyVisitInTx` 被当前 tab 接管
- 不接管也不创建 → 进入新 visit 路径
