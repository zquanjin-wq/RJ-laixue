# 课程视频后台导出体验设计

状态：P0 + P1 已实现，待 Preview 迁移与部署验证  
范围：课程 MP4 导出；不改变课件播放、课程保存和 RuntimeStore 逻辑

## 1. 目标

老师点击“导出课程视频”后，不需要留在当前页面等待完整渲染。系统应明确告诉老师什么时候可以离开、去哪里查看、任务是否成功，并允许在课程管理页直接下载成品。

固定结果入口：**课程管理 → 视频导出**。课程卡片同时显示该课程最新一次导出状态。

## 2. 当前问题

当前链路为：

1. 浏览器生成课堂 ZIP；
2. 浏览器将 ZIP 上传到课程存储；
3. 主应用把 ZIP 提交给独立渲染服务；
4. 当前课堂页每 3 秒查询一次任务；
5. 查询发现渲染完成后，主应用才从渲染服务取回 MP4，上传课程存储并将任务标记为成功。

第 1、2 步依赖当前浏览器，不能承诺老师立即关闭页面。更重要的是，第 5 步目前依赖课堂页轮询；老师离开后，任务可能已经在渲染服务完成，但主应用没有及时收回文件和更新状态。

因此，单纯增加“可以离开”提示不成立，必须先补后台任务收尾能力。

## 3. 用户流程

### 3.1 点击导出

点击后打开轻量任务面板，分成两个阶段：

- **准备素材**：显示“正在整理第 X/Y 个章节，请暂时不要关闭此页面”。老师可以继续查看或编辑页面，但关闭标签页会中断本次准备。
- **后台生成**：ZIP 上传并被服务端接受后，显示“视频已转入后台生成，现在可以离开此页面”。

后台生成提示提供两个操作：

- `继续编辑`
- `查看视频任务`

同时明确：**视频采用点击导出时的课件版本，之后的编辑不会进入本次视频。**

### 3.2 离开页面后

老师进入“课程管理”时，页面顶部显示“视频导出”入口及未完成任务数量。每门课程卡片显示最新任务：

| 状态 | 展示 | 操作 |
| --- | --- | --- |
| 准备中 | 正在准备视频素材 | 返回原页面继续；或取消 |
| 排队中 | 已提交，等待渲染 | 查看详情；取消 |
| 生成中 | 正在生成视频 · X% | 查看详情；取消 |
| 已完成 | 视频已生成 | 下载 MP4；再次导出 |
| 失败 | 显示可理解的失败原因 | 重试 |
| 已取消 | 已取消 | 再次导出 |

“视频导出”列表按时间倒序显示任务、课程名、发起时间、状态和操作。V1 保留最近任务即可，不先做复杂归档管理。

### 3.3 当前课堂页

导出菜单不再用一个长期旋转的按钮承担全部反馈：

- 无任务：`导出课程视频`
- 准备阶段：`正在准备素材 X/Y`
- 后台阶段：`后台生成中 X%`，按钮仍可打开任务详情，不禁用整个菜单
- 完成：`下载最新视频`
- 失败：`生成失败，点击查看`

任务完成时，如果老师仍在线，显示一次站内提示：“《课程名》视频已生成”，提供直接下载按钮。老师不在线时，不要求浏览器通知或邮件；下次进入课程管理即可看到结果。

## 4. 后台机制

### 4.1 任务收尾必须脱离课堂页

增加服务端定时收尾器，每分钟处理 `running` 任务：

1. 查询渲染服务状态；
2. 更新结构化进度；
3. 渲染成功后取回 MP4；
4. 上传课程存储；
5. 将任务更新为 `succeeded`；
6. 渲染失败或取消时写入终态和用户可读错误。

在当前腾讯云 CVM + Dokploy 架构下，V1 使用 Dokploy Schedule 调用主应用的内部收尾端点。课堂页仍可轮询以获得即时反馈，但轮询不再承担任务完成的必要职责。

不要让渲染服务直接持有 Supabase service role；文件归档和权限继续由主应用负责。

### 4.2 API

保留现有单任务接口，并补充：

- `GET /api/video-exports`：列出当前用户有权查看的任务；支持按课程和状态筛选。
- `GET /api/courses/:id/video-exports`：不传 `jobId` 时返回该课程的任务列表和最新任务。
- `POST /api/internal/video-exports/reconcile`：供 Dokploy Schedule 触发后台收尾。

列表接口只返回当前用户自己的课程任务；管理员按现有管理权限查看。下载仍使用短期签名地址。

### 4.3 数据

沿用现有 `course_video_export_jobs`，增加结构化字段：

- `progress_current`
- `progress_total`
- `source_label`（例如“8 月 31 日 16:42 的课件版本”）

状态、进度和错误不得只藏在 `message` 字符串里。`message` 继续作为界面文案，业务判断使用结构化字段。

V1 每门课程只允许一个非终态任务，避免老师因为没看到反馈而连续创建多个相同视频。已完成任务不阻止再次导出新版本。

## 5. 准备阶段体验

当前准备阶段包含页面截图、音频整理、ZIP 打包和上传。为避免“像卡死”：

- 编译器回调章节进度：`正在整理章节 3/12`；
- 上传时显示 `正在上传视频素材`；
- 超过 10 秒时补充说明“素材较多时可能需要几分钟”；
- 上传成功后立刻切换为“可以离开”；
- 准备失败时不创建假后台任务，直接说明失败环节并允许重试。

如果老师在准备阶段关闭页面，本次任务显示为“准备未完成”，而不是一直停在“上传中”。服务端定时把长时间未提交的 `uploading` 任务标为失败。

## 6. 后续优化：免浏览器上传

正式 V1 仍需要浏览器把当前课件画面编译成 ZIP，因此只能在“素材提交完成”后允许离开。

下一阶段可以消除这段等待：课程保存到云端时同步保存视频导出所需的页面快照和音频引用；导出时服务端直接从云端课程源构建渲染包。届时老师点击后即可立即离开，无需浏览器截图、打包和上传。

该优化应独立实施，不与本轮后台任务体验混在一起：先让“提交后可离开、结果找得到”可靠工作，再优化“点击后立刻离开”。

## 7. 实施顺序

### P0：真正后台化

- 增加任务列表接口和后台收尾器；
- Dokploy Schedule 定期收尾；
- 验证关闭课堂页后任务仍能进入成功或失败终态；
- 清理长期停留在 `uploading` 的任务。

### P1：老师看得见、找得到

- 新增“课程管理 → 视频导出”任务列表；
- 课程卡显示最新状态和下载入口；
- 提交成功后明确提示“现在可以离开”和查看路径；
- 当前页面显示结构化进度与完成提示。

### P2：准备阶段进度

- 页面截图、ZIP 编译、上传三个阶段分别反馈；
- 章节级准备进度；
- 准备阶段离开时给出准确提醒。

### P3：直接使用云端课程源

- 保存视频导出所需的云端快照；
- 服务端构建渲染包；
- 将“可以离开”的时间点提前到点击导出之后。

## 8. Preview 验收场景

1. 提交成功后关闭课堂标签页，任务仍完成，并能在课程管理下载。
2. 在另一台浏览器登录同一老师账号，可以看到任务及下载结果。
3. 生成过程中继续编辑课程，本次视频保持提交时版本，界面说明一致。
4. 渲染失败时任务进入失败终态，显示原因并允许重试。
5. 同一课程生成中再次点击，不重复创建任务，而是打开现有任务。
6. 准备阶段关闭页面，任务不会永久停留在“上传中”。

Preview 全部通过后再单独决定是否进入正式环境。
