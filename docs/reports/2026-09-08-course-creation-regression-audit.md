# 课程创建与交付链路回归盘点（2026-09-08）

## 结论

本轮按真实用户路径复核了 AI/PPT 创建、配音、保存、课程管理、再次编辑和视频导出。生产构建可通过，最近 48 小时 11 个持久化成课任务全部成功；但审计发现两个需要立即修正的跨模块缺口、两个存量数据问题，以及一组会削弱回归可信度的测试基线问题。

## 已修正并通过校验

1. **编辑权限不再由 URL 或界面可见性推断。** 作者权限由课堂页面完成一次鉴权后显式传递到播放和编辑界面；学员手工添加 `?editor=1` 不再获得编辑入口或触发云端自动保存。
2. **移除编辑界面的第二套独立鉴权。** 顶部操作区和编辑界面不再各自发起身份加载，避免身份水合与课程初始化竞争导致客户端异常。
3. **未保存修改不能生成视频。** 新增课程级浏览器会话状态：`unknown → dirty → saving → saved/failed`。数据库的 `save_state=ready` 只代表上一次云端快照，不能再掩盖本地刚发生但尚未完成自动保存的编辑。
4. **播放/编辑切换不会丢失未保存状态。** 两套界面卸载、重挂载时保留同一课程的 dirty/failed 状态；切换课程时才重置。
5. **清理课程音色调试日志。** 不再在浏览器控制台输出课程音色配置。

对应提交：`43c36e00 fix: keep author actions and cloud state consistent`

## 尚未闭环的高优先级问题

### P0：所谓“外部 Skill/API”目前不是完整可调用链路

现有 `/api/v1/pptx-classrooms` 只接受已经存在的 `sourceId + courseId + sourceRevision`。但 PPTX 上传、浏览器解析、源文件登记、课程草稿创建仍只支持网页登录态和浏览器端 importer。外部 Skill 不能仅凭 API Token 上传一个 PPTX 并完成成课，因此当前能力应定义为“对站内已导入 PPTX 发起增强任务”，不能定义为完整外部 PPT 成课 API。

闭环需要新增 API Token 版的分段协议：创建上传会话并获得签名地址 → 上传确认与源登记 → 服务端/受控解析任务生成正式草稿 → 发起 AI 成课 → 轮询结果。由于当前 importer 明确为 browser-only，解析步骤不能简单复用现有接口，需要单独实现可部署的服务端解析器或隔离的浏览器解析 worker。

### P1：全量测试基线失真

全量测试结果为 325 个测试文件中 317 通过、3 跳过、5 失败；2641 个用例中 2590 通过、25 跳过、26 失败。失败主要来自：

- 两个已从当前分支消失、但测试仍引用的历史脚本；
- 学习任务测试仍按旧的鉴权 mock 方式运行，Next.js 16 下调用了真实请求上下文；
- 数据库基础测试没有同步 `0014_api_tokens.sql` 及新增用户外键前置数据；
- 一个 TTS 重试测试未补齐现在必需的课程级音色配置。

这些失败并非本轮改动引入，但会导致“全量测试红灯”长期被忽略。应先修复测试基线，再把本报告覆盖的主链路用例设为发布必跑项。
