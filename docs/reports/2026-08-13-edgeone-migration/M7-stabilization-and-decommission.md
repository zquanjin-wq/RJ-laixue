# M7 任务卡：稳定观察与 Vercel 下线决策

**编号**: MIG-EO-M7
**前置**: M6 切流完成
**状态**: ⏸️ 未开始
**预计**: 7 天观察 + 0.5 天决策
**生产权限**: 仅观察；下线另行签字

## 1. 任务目标

确认 EdgeOne 在真实生产流量、额度、国内网络和重任务负载下持续稳定，并基于证据决定继续运行、局部回退或下线 Vercel。

## 2. 每日观察清单

- [ ] 页面流量、EdgeOne/Worker 请求量、5xx、超时和 CPU/内存。
- [ ] 登录、建课、保存、发布、学习任务成功率。
- [ ] 任务 queued/running 时长、成功率、重试率、死信数量。
- [ ] Supabase 数据库、Auth、Storage 延迟和错误率。
- [ ] 国内移动/联通/电信与海外访问抽测。
- [ ] EdgeOne 免费额度、构建次数、函数调用、GB-s、KV/Blob 使用量。
- [ ] Vercel 是否仍收到非预期生产流量。

## 3. 第 3 天检查点

- 若出现持续性能回退、额度异常或任务积压，保持 Vercel，不进入下线讨论。
- 若 Supabase 成为主要延迟瓶颈，单独创建“数据平台国内化评估”，不得扩张本迁移范围。
- 若 EdgeOne 产品或商业化条件发生变化，重新评估 TCO 和退出成本。

## 4. 第 7 天退出门禁

仅当全部满足时，允许提出 Vercel 下线申请：

1. 连续 7 天 5xx < 0.5%，无未关闭 P0/P1；
2. 关键业务成功率不低于迁移前基线；
3. 国内性能达到总规划指标；
4. 无丢任务、双执行、不可恢复积压；
5. 完成一次非事故回滚演练，RTO ≤ 15 分钟；
6. EdgeOne 配额与未来付费风险由负责人书面接受；
7. Vercel 无独占 Secret、Cron、域名、日志或回滚依赖。

## 5. Vercel 下线步骤

下线必须作为独立变更窗口执行：

- [ ] 导出最终环境变量名称、部署记录和账单，不导出 Secret 明文到仓库。
- [ ] 删除 Vercel 自定义域名绑定，保留项目只读观察 7 天。
- [ ] 确认无流量后取消付费能力和自动部署。
- [ ] 再观察 7 天后，由负责人决定归档还是删除项目。
- [ ] 更新 README、运维手册、故障联系人和架构图。

## 6. 决策选项

- **A：完成迁移**——EdgeOne 为主，Vercel 进入归档/删除流程。
- **B：双平台保底**——保留 Vercel 最小可用项目，接受固定成本。
- **C：局部回退**——Web 留在 EdgeOne，指定 API 回到其他 Node 平台。
- **D：整体回退**——DNS 指回 Vercel，另立重新选型任务。

## 7. 交付物

- 遗留问题清单及负责人。

## 8. 边界

- ❌ 未签字不得删除 Vercel 项目、Secret、部署记录或取消关键服务。
- ❌ 稳定观察期不夹带数据库迁移、框架升级或无关重构。
