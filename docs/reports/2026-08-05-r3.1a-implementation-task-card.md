## 1. 任务目标

将 playback 影子写的 session 身份从「每 stage 一个 `pb:<stageId>`」迁移到「每 visit 一个 `pb:<stageId>:<visitId>`」，实现 completed 后新播放周期自动获得新 session，从结构上消除「completed 后 append → 409 INACTIVE_SESSION」的主路径（残余窗口由已签字的 R3.0 中央分类兜底）。

唯一权威设计文档：`docs/reports/2026-08-05-r3.1a-playback-visit-session-design.md`（693 行）。实施必须逐条对照该文档，任何偏离必须在实施报告中显式声明并说明理由。

## 2. 实施范围（7 个模块，按依赖顺序）

### M1 Dexie v18 schema + 迁移（设计 §5.1/§5.2）
- `lib/utils/database.ts`：`version(18)`，新增 `playbackVisits`（`visitId, [stageId+status], [tabOwnerId+stageId]`）与 `playbackVisitStates`（`visitId, [stageId+visitId]`）两表；`PlaybackVisit` / `PlaybackVisitState` 接口按设计 §1.5-§1.7
- v17→v18 upgrade：旧 `playbackState` 行 → legacy visits（`visitId = legacy-<stageId>`，`sessionId = pb:<stageId>` 原样保留，`isLegacyAdopted: true`）+ 复制到 visitStates；旧表不删除
- ⚠️ 设计 §5.2 迁移代码中 `createdByOwnerAt` 字段不存在于 §1.6 接口定义，实施时以 §1.6 字段清单为准（视为设计笔误，在实施报告中记录即可，不算偏离）

### M2 generateHexId 统一（设计 §1.3）
- 全部 visit/owner ID 用 `generateHexId(16)`（32 hex chars），禁止 `crypto.randomUUID()`

### M3 tabOwner claim 协议（设计 §1.4）
- `claimTabOwnerId()` async + `startHolderListener` 持续持有 + `probeOwnerId` Promise/setTimeout 150ms + instanceId 字典序 tiebreak + `currentOwnerId` 短路（防自碰撞）+ beforeunload 关频道
- 让出后 `currentOwnerId = null`，旧 outbox 继续排空，不删数据

### M4 visit 生命周期事务函数（设计 §1.8/§1.9/§2.2）
- `claimOrReuseVisitInTx`：adoption 为第一步（`[stageId+status]` 索引 + `isLegacyAdopted` 标记清除），再查 `[tabOwnerId+stageId]`，最后创建新 visit；**不嵌套 db.transaction**
- `completePreflightInTx`：三路 enum（`idempotent` / `cycle_completed` / `proceed`），覆盖设计 §1.8 的 A/B/C 三个 edge case；`SnapshotEventMismatchError`、`VisitCycleCompletedError`
- `checkVisitCompleted`：同事务完成「凭据检查 + visit.status 翻转 + completedCredentialAt 写入」（§1.9 不变量）

### M5 persistSnapshotWithComplete 主流程（设计 §2.5）
- 四表同事务：`playbackVisits, playbackVisitStates, runtimeOutbox, runtimeChainHeads`
- create 凭据式入队（仅 `visit.createEntryId` 不存在时）、append 链式依赖、completed 时 `enqueueCompleteWithCASInTx`（status.dependsOnEntryId = appendId，方向不得反）
- 事务内入队需要 `_qEnqueue` 式的事务内 helper（不触发独立事务/网络）；复用现有 outbox enqueue 逻辑时不得破坏其语义
- `VisitCycleCompletedError` 由调用方 catch → 重新 claim（获得新 visit）→ 重试

### M6 现有链路接线
- `lib/utils/playback-persistence.ts` 与 `lib/runtime/shadow-writer.ts` 的 playback 影子写入口切换到 visit 模型；A1 本地落盘/A2 影子写既有行为（5s trailing 节流、关键事件 flush、串行写入、pending 条件清除、superseded、completed PATCH 补偿）**不得回归**
- 旧 `pb:<stageId>` 失败条目不阻断新 visit（设计 §3.2）

### M7 单元门禁（设计 §4，20 场景）
- 20 个 E2E 场景的客户端逻辑单测，含 adoption #17-#20、防自碰撞 #14 短路断言、#16「重复 complete 后 runtimeOutbox 条目数不增加」
- 回归：`tests/runtime-outbox`、`tests/playback`、`tests/quiz/quiz-outbox.test.ts`、`tests/runtime-shadow` 全绿
- `tsc --noEmit` 零新增错误（既有 4 个 pg/pg-mem 错误为基线）
